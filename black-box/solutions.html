Learning target

Students distinguish essential from incidental information, organize related data under meaningful names, and replace a detailed procedure with a clear operation. They should be able to explain that abstraction hides complexity without eliminating it.

Breakfast Catapult

Keep: Table 7 Coordinates, Launch Angle, Bread Type, Toast Weight, Landing Zone Clear.

Groups: Targeting (Table 7 Coordinates, Launch Angle, Toast Weight); Breakfast (Bread Type); Safety (Landing Zone Clear).

Procedure: Check landing zone → Load toast → Set angle → Charge spring → Release toast.

School Bus

Keep: route number, next stop, stops until destination, stop requested, service alert.

Key idea: engine temperature and battery voltage might matter greatly to a mechanic but not to this passenger. Relevance depends on context.

Moon Base

Keep: leak location, crew clear, oxygen reserve, hatch seal status, pressure difference.

Key idea: an abstraction can be compact while still preserving safety-critical confirmation.

Common misconceptions

  • “Good abstraction means hiding as much as possible.” Missing essential details makes an interface unusable or unsafe.
  • “A detail is always relevant or irrelevant.” The user and goal determine relevance.
  • “The simple button removes the work.” The internal procedure still runs.

Discussion prompts

  • Which hidden detail would become relevant if the user changed from operator to mechanic?
  • When can hiding information become dangerous?
  • What familiar object is a “black box” for you? What simple controls does it expose?
  • Could two equally good abstractions organize the same details differently? Defend your answer.
