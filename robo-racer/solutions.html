Facilitation notes for an algorithmic-thinking lesson.

Learning target

Students create an ordered sequence of instructions, predict the interaction between that sequence and a changing environment, test it, and debug from an execution trace.

Useful vocabulary after students have attempted a course: algorithm, sequence, state, execution, trace, prediction, debugging, iteration.

How the simulation works

  1. The student selects five cards from a constrained-random hand of eight. Every hand includes at least one left turn, one right turn, and four forward cards.
  2. One card executes relative to the robot's current facing.
  3. Entering a conveyor or gear ends the current movement card. A conveyor follows every belt tile and moves the robot one square off its exit; an element on that exit square then resolves. Only after that does the next register execute.
  4. Active lasers and pits both cause an immediate reboot at the course's starting square, end the current program, and deal a fresh hand.
  5. The process repeats for all five registers. Lasers toggle between rounds on the Laser Lab course.

Walls stop movement. A move-two or move-three card stops when a wall or pit interrupts it. The goal also stops movement in Easy mode; in Hard mode the robot may continue through it.

Goal modes: Easy mode completes immediately when the robot touches the goal. Hard mode allows the robot to pass through the goal and succeeds only when all five registers finish with the robot occupying it.

Course intentions

Each course has three handcrafted layouts: Core Route, Crossflow Route, and Switchback Route. They use different starts, goals, conveyor networks, gear sequences, walls, pits, and laser rows while retaining the course's intended concept.

1 · Training Floor

Introduces relative movement and a single environmental action. Ask students to identify which movement came from their algorithm and which came from the board.

2 · Sorting Works

Requires composition: the student's sequence combines with conveyor translation and gear rotation. More than one solution may be valid because the hand is random.

3 · Laser Lab

Adds state that changes over time. A turn can function as a deliberate wait, demonstrating that an instruction can be useful without changing position.

Discussion prompts

Where did your robot's actual state first differ from the state you predicted?

Can you change only one instruction and improve the result?

Does the same instruction always produce the same position? What other state matters?

How is the execution trace similar to output from a computer program?

Common misconceptions

  • “Forward means up.” Forward is relative to the robot's direction.
  • “The board changes after the whole program.” It activates after every register.
  • “A failed run was wasted.” A failure provides a trace locating the earliest incorrect assumption.
  • “There is one correct program.” Random hands and alternate routes support many correct algorithms.
